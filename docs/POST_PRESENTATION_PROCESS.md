# Post-Presentation Process

1. Collect feedback with `PRESENTATION_FEEDBACK_TEMPLATE.md`.
2. Deduplicate and classify defects, required business decisions and optional enhancements.
3. Obtain owners and written acceptance criteria.
4. Identify changes required before Firebase versus before pilot.
5. Reopen frontend work only through an approved change list.
6. Re-run type-check, lint, unit, presentation dataset, build/PWA and full E2E.
7. Issue a new immutable presentation candidate identifier; do not overwrite Candidate 1.
8. Obtain management/system-owner approval.
9. Authorize Phase 10 separately before any Firebase configuration or integration.

Repository freeze reference for Candidate 1 is the working-tree state recorded on 2026-07-31; no commit was created because the existing worktree contains unrelated user changes.
